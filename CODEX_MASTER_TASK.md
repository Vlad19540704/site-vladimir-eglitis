# Codex: задание для проекта «Сайт»
**Режим работы:** автономный полный цикл по AUTONOMOUS_EXECUTION.md. Сначала локальное тестирование; после точечного подтверждения покупки, домена и выпуска — самостоятельные покупка/настройка нового VPS и публикация. Старое ограничение «только локальная реализация» снято; сервер памяти Лилы не трогать.

## Цель
Превратить `site/` в полностью готовый к предпубликационной приёмке статический сайт частного консультанта по алкогольной зависимости, не переделывая утверждённый тёплый визуальный язык (`APPROVED_REFERENCE/visual_approved.png`). Задача — качественная инженерная сборка, не свободный дизайн с нуля.

## Этап 0 — аудит (сделать первым, показать отчёт)
- Изучить источники `site/`, скриншот, `AGENTS.md`, решения/блокеры.
- Проверить несоответствия v0.8 screenshot: цвета, типографика, ритм, адаптив, реальные placeholder-и, навигация. Отдельно указать какие части скриншота вообще пока не в коде.
- Снять Playwright скриншоты 1440x900, 768x1024, 390x844, 320x700, сравнить с референсом в разумных пределах (различные пропорции).
- Создать план узких diff-патчей с перечнем затрагиваемых файлов; не менять тексты/палитру без запроса.

## Этап 1 — локальная сборка
- Консолидация лишних устаревших файлов CSS/JS с сохранением нужных эффектов.
- Одна короткая навигация: Главная, Консультация, О Владимире, Статьи, Контакты. Условия и полный прайс — только на коммерческой странице или в логично включённом разделе там; не дублировать прайс на главной.
- Тексты первой страницы сверять с `DECISIONS_AND_BLOCKERS.md`: никакой помощи родственникам, географии и AI-штампов.
- Две статьи уже внесены. Сохранить дословно их тексты, заменить только техническую обёртку по нужде.
- Настроить единые существующие стили через CSS variables, состояния hover/focus, адекватные tap areas.
- Оставить пустую реальную photo-zone с аккуратной заглушкой; НЕ брать похожего персонажа из фотостока/AI.
- На каждой странице понятный доступ к прямым контактам; внешние персональные ссылки НЕ придумывать.

## Этап 2 — SEO и качество
- Задать ручные Title/description/canonical per page, и `Article` JSON-LD на две статьи (author без выдуманных регалий, даты только реальные).
- Добавить скрипт генерации sitemap.xml из реально опубликованных страниц после задания домена. `robots.txt` staging закрыт; production отдельно генерируется только после пройденного preflight.
- Исключить 3 неутверждённых статьи, дубли и архивы из production.
- Google Search Console / Яндекс Вебмастер: только подготовить инструкции подтверждения. Аналитика/Метрика — без передачи содержимого форм и чувствительных данных.
- Вводные страницы информационные: не создавать ложных `MedicalBusiness` или отзывов/FAQ schema только ради поисковой разметки.
- Проверить CWV/Lighthouse локально; главная картинка оптимизирована, нет загрузки тяжёлых библиотек.

## Этап 3 — инфраструктура, затем выполнение по подтверждению
- Подготовить отдельный runbook под новый VPS VDSina 1 CPU/1GB RAM/10GB SSD, Caddy+HTTPS, ограничения SSH, firewall, автообновления, отдельный непривилегированный пользователь, внешние backups, rollback, health checks.
- Сначала подготовить конфиги/инструкции; после утверждения нового VPS Codex самостоятельно проводит развертывание и проверки. НЕ соединяться с личной памятью Лилы и НЕ править старый VPS.
- Codex самостоятельно подбирает варианты, запрашивает у Владимира выбор и согласие на покупку, затем покупает и настраивает через доступный браузер; никакого выдуманного домена в production.
- Jivo бесплатный только через feature flag/плейсхолдер; реальный скрипт только после правовой и технической проверки, не собирать диагнозы/сведения о клиентах.

## Выход
1. Структурированный отчёт аудита.
2. Локальная сборка и инструкция одной команды для запуска.
3. Снимки экранов 4 ширин до/после и указание расхождений.
4. Автотесты (все внутренние ссылки, отсутствие фальшивых href, нет горизонтального скролла, menu keyboard, H1, metadata, two articles, no unapproved posts, accessibility).
5. SEO/deploy/runbook без подключения живых сервисов.
6. Предпубликационный чек-лист — блокировать выпуск при неподтверждённых контактах, реальном фото, условиях и оплате.
Не утверждай, что результат опубликован или визуально соответствует эталону, пока это не измерено и не утверждено Владимиром.
