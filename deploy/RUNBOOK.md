Первоначальный пароль удалён с локального компьютера после проверки SSH-ключа. Пользователь `deploy` входит по ключу; парольный и root SSH отключены. ## Порядок дальнейшего развёртывания только на новом сервере

1. Зафиксировать IP, образ ОС и SSH host fingerprint локально вне Git. Создать отдельный SSH-ключ для этого VPS; секретную часть не переносить в репозиторий.
2. Войти через выданный VDSina способ, создать непривилегированного пользователя `deploy`, добавить его публичный ключ. Проверить новый вход в отдельной сессии. Лишь затем отключить парольный SSH и root login.
3. Обновить ОС, включить автоматические security updates. Настроить firewall: входящие 22/tcp (по возможности с IP администратора), 80/tcp, 443/tcp; остальные входящие закрыть. Проверить новый SSH-вход до закрытия текущей сессии.
4. Установить Caddy из официального репозитория. Создать `/srv/site/releases` и `/srv/site/current`, доступ записи только `deploy`, чтение для Caddy. Подставить реальный домен в `Caddyfile.template`; сначала проверить `caddy validate`.
5. Загрузить только release allowlist из `scripts/build_release.py`. Сделать новую папку релиза по commit SHA и атомарно переключить symlink `current`. Сохранить предыдущий symlink для отката.
6. После подтверждённой покупки домена задать A/AAAA DNS только на новый IP. Проверить DNS с нескольких резолверов, затем HTTPS, сертификат, 200/404, robots, sitemap, canonical, внутренние ссылки, мобильный рендер и отсутствие утечек в access logs.
7. Внешняя резервная копия: зашифрованный архив релиза, Caddyfile и инструкции восстановления в отдельном хранилище вне VPS. Не включать переписки/медицинские данные в backup. Проверить восстановление в временный каталог и сравнить SHA-256; записать дату и результат. Хранить минимум два релиза для быстрого отката.
8. Health check: HTTP GET главной и контактной страницы, срок TLS, свободное место и доступность Caddy. При ошибке уведомление владельцу через согласованный канал. Откат: вернуть прежний symlink и проверить 200 + TLS.

## Предпубликационный gate

`python scripts/build_release.py --domain <реальный-домен> --checklist release_approval.json` сознательно блокируется сейчас. Нужны подтверждённые контакты, реальное фото, рублёвые условия, страница политики данных и юридических условий, даты статей, визуальная приёмка, владение доменом и отдельное разрешение на запуск. Пример полей в `release_approval.example.json`; живой файл игнорируется Git.

## Поисковые сервисы после запуска

- Google Search Console: добавить Domain property, разместить выданный Google TXT в DNS, дождаться проверки, отправить `sitemap.xml`. Учетную запись авторизует Владимир.
- Яндекс Вебмастер: добавить домен, разместить выданный TXT в DNS, проверить права, отправить sitemap. Учетную запись авторизует Владимир.
- Яндекс Метрика: до установки согласовать политику данных и режим аналитики; не отправлять в события формы, диагнозы, текст переписки и персональные URL. Использовать только счётчик после согласия, если оно требуется принятой политикой.
- Jivo: бесплатный тариф «Начальная» технически включает чат сайта и каналы MAX/Telegram, но текущий код виджет не грузит. Перед включением нужны согласованная политика обработки данных, договорные условия и режим, исключающий сбор чувствительных сведений без надлежащего основания. Только живой оператор.
