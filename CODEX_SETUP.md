# Что подключить Codex и как работать без AI-самодеятельности

## Обязательный минимум
1. **Локальный Git-репозиторий** из папки этого handoff (не публичный до ревью), Node.js LTS и Python 3 для тестов. Доступ Codex только к каталогу проекта. Коммиты после каждого принятого этапа и отдельная ветка на визуальные правки.
2. **Редактор и Codex**: VS Code или Codex CLI с доступом к репозиторию и возможностью запускать локальный терминал. Не выдавать глобальный SSH или весь домашний каталог.
3. **Playwright с Chromium** для реальных screenshots по заданным размерам, smoke-тестов маршрутов и проверки мобильного меню, CTA/клавиатуры. Не заменять скриншоты описанием от модели. Firefox/WebKit по возможности на втором проходе.
4. **Скриншот-референс и правила в репозитории:** `APPROVED_REFERENCE/visual_approved.png`, `AGENTS.md`, текущие авторские HTML. Это важнее любой очередной «подключённой нейросети».
5. **Локальный preview** `python -m http.server 8080` из site/. Тестировать через http://localhost, не file://.

## Очень полезно, но только при фактическом использовании
- GitHub **private repo + PR/review**: история изменений, CI и откаты. Доступ Codex только к одному репозиторию. Если Codex работает через облачный GitHub, подключить этот репозиторий в его настройках, а не весь аккаунт.
- **Browser/devtools** для чтения performance/console/accessibility; Playwright уже покрывает большинство задач. Не подключать одновременно 5 разных браузерных MCP без нужды.
- Если используем OpenAI API на следующем этапе — официальный **OpenAI Developer Docs MCP** (read-only) https://developers.openai.com/mcp; сейчас для статического сайта НЕ нужен.
- Figma MCP — только если позже создадим исходный дизайн в Figma. По одному одобренному PNG инструмент Figma не создаст дизайн-систему автоматически.
- Для SEO: доступ к Яндекс Вордстату для сбора запросов. Яндекс Вебмастер / Google Search Console — ПОСЛЕ покупки домена и его подтверждения; не передавать Codex административные пароли.

## Сервер
- Codex на локальном этапе НЕ нужен доступ к новому VPS. Сначала подготовить Caddy config, тестовый deploy-script и runbook.
- После покупки VPS: создать отдельный deploy account с SSH-ключом для этого сервера и ограниченным каталогом. Не использовать тот же ключ, что у личной памяти Лилы; не копировать ключ в чат/репозиторий.
- Публичные токены аналитики/виджета только после выбора провайдера и договора. Секреты в env / secret store вне Git.

## Последовательность
Сначала AUDIT + screenshot diff; потом два локальных PR: (1) content/navigation/SEO и (2) точная вёрстка + a11y. Затем тесты, отдельное ревью и лишь потом деплой. Так проще отличить смысловые изменения от дизайнерской самодеятельности.
